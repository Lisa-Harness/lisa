# hosts.core — Shared Host Runtime

Inherits all rules in `.github/instructions/python-development.md` and
`.github/instructions/code-quality.md`. The rules below are additive and
specific to `hosts/core/`.

## Architectural role

`hosts.core` is the transport-neutral host runtime. It owns:
- Typed configuration (`HostConfig`) — frozen, constructed once at startup.
- Typed runtime state (`HostRuntime`) — mutable, owns provider clients,
  MCP pool, token counters, thread/log paths, and last-turn diagnostics.
- Transport callback protocol (`TransportCallbacks`) — the Option B seam
  for delivering turn events to transport hosts.
- The transport-neutral `handle_message` dispatcher.
- Pure configuration-resolution helpers (timezone, streaming, log level).
- Provider completion dispatch (Azure OpenAI, OpenAI, Anthropic, Ollama, Google).
- MCP config compilation from `mcp_servers.yaml`.
- Content root and pack activation discovery.
- Thread persistence and slice (state provider).
- Host command dispatch (`/help`, `/settings`, `/tokens`, `/debug`, etc.)
  producing structured text, not rendered panels.

## Transport boundary

**Never import**: `rich`, `typer`, `aiohttp`, `prompt_toolkit`, `PIL`,
`pystray`, `webbrowser`, or any transport-specific package.

**Never call**: `console.print()`, `Console()`, `typer.Option()`,
`webbrowser.open()`, or any rendering/delivery function.

The runtime delivers events through `TransportCallbacks`. Transport hosts
(cli, web, vscode) implement the callbacks to render in their native surface.

## Module decomposition target

- `config.py` — `HostConfig`, `SliceConfig`, `StreamingConfig` (frozen dataclasses).
- `config_resolver.py` — pure timezone/streaming/log-level resolution functions.
- `runtime.py` — `HostRuntime`, `TokenCounters`, `TurnContext` (mutable state).
- `callbacks.py` — `TransportCallbacks` protocol, `NullTransport`, `DelegatingTransport`.
- `types.py` — type aliases (`ModelResolver`, `CompletionProvider`, `ToolExecutor`).
- `handle_message.py` — transport-neutral message dispatcher.
- Future modules: `providers.py`, `mcp_pool.py`, `content_roots.py`,
  `thread.py`, `state_provider.py`, `context_assembly.py`.

When a new responsibility accumulates, extract it to a new submodule
before it grows. Do not add new logic to `handle_message.py` beyond
dispatch routing.

## MCP pool lifecycle

The MCP pool **must** be started and closed inside the host's real event
loop. `HostRuntime.start()` and `HostRuntime.aclose()` are async and must
be called from the same event loop that executes turns. Never build or
enter MCP resources during sync initialization — anyio cancel scopes bind
to the task that entered them.

## No background schedulers

Follows the same opportunistic, pressure-driven work pattern as Little Lisa.
Do not introduce `cron`, `sched`, `threading.Timer`, or any wall-clock
background scheduler. Housekeeping runs inside the slice budget.

## No compat or migration

When adopting a new pattern, hard cutover. No shim layers, no dual-path
code. The old code goes away.

## Test seams

Tests construct `HostConfig.from_env(...)` and `HostRuntime(config)` directly.
No `monkeypatch.setattr` on module-level functions is needed for the core
interface tests. When testing provider/MCP behavior, inject fakes via the
runtime's setter properties or constructor parameters.
