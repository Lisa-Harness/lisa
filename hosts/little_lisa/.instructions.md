# Little Lisa Example Host

Inherits all rules in `.github/instructions/python-development.md` and
`.github/instructions/code-quality.md`. The rules below are additive and
specific to `hosts/little_lisa/`.

## Module decomposition target

`main.py` is the orchestration shell only. It owns the CLI entry points, the
REPL loop, and thin re-exports for test compatibility. Pure logic lives in
focused submodules:

- `config.py` — timezone / log-level / streaming / slice resolution.
- `token_accounting.py` — token ledger and session summaries.
- `turn_logging.py` — JSONL log-record assembly.
- `model_runtime.py` — model manifest loading and resolution.
- `model_manifest.py` — manifest file discovery.
- `desktop.py` — localhost web-host callbacks.
- `tray.py` — system-tray launcher.

When `main.py` grows a new responsibility, extract it to a new submodule
before it accumulates. Do not add new logic to `main.py`.

## Test seams (preserve during refactors)

Tests use `monkeypatch.setattr(little_lisa, "_resolve_model", fake)` and
`monkeypatch.setitem(little_lisa._RUNTIME_STATE, key, value)`. To preserve
these seams:

- All test-visible function names remain on `main.py`'s surface (re-imported
  from submodules or defined as thin wrappers).
- `_RUNTIME_STATE` stays a plain dict (not a typed dataclass) so tests can
  mutate it directly — unless the refactor introduces a typed model with
  `__getitem__`/`__setitem__` compatibility, which must be verified against
  the existing test suite first.
- Submodule imports use `try: from .module import ... / except ImportError`
  so `main.py` also works as a standalone script.

## No background schedulers

Little Lisa uses opportunistic, pressure-driven work piggybacking on the
natural turn cadence. Do not introduce `cron`, `sched`, `threading.Timer`,
or any wall-clock background scheduler. Housekeeping runs inside the slice
budget on `/consolidate` or the optional post-turn slice.
